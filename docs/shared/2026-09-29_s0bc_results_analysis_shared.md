# S0-B/C 상태 모델 실험 결과와 한계

- 문서 ID: `DOC-20260929-s0bc-results-analysis-R1`
- 기준일: 2026-09-29
- 상태: `completed` — B 단독 `not_selected`, C validation 상태 안정화 기준 통과

## 핵심 결론

S0-B의12epoch 학습과 S0-C의44조건 비교·고정 평가를 완료했다.
**S0-B는 프레임 분류를 개선했지만 상태 전환 감소 기준을 충족하지 못했다.**
**S0-C는 상태 연속성을 크게 개선했으나 테스트 낙상 재현율이 낮아졌다.**
상태 안정화 연구 기준선 확보와 낙상 경보·회복 이벤트의 운영 적합성은 구분한다.

## 방법과 선택

- **S0-A**: 동결 표현 위의16-class 선형 상태 분류기, sqrt weighting, validation에서 선택한epoch4.
- **S0-B**: A의 동결 출력에 residual temporal correction을 더해12epoch 학습했다.
  실질 배치1024, FP32, 사전 고정한 학습·평가 조건을 유지했다. Validation
  Macro-F1 → SegmentF1@50 → Edit 순서로epoch7을 선택했다.
- **S0-C**: A/B 각각 raw·EMA·EMA와 연속확인 규칙의22조건, 총44조건을 비교했다.
  각 입력의 자기 raw 기준으로 Macro-F1 하락≤0.5%p, fall recall 하락≤2%p,
  상태 전환 감소≥25%인 후보만 통과시킨 뒤 SegmentF1@50 → Edit → Macro-F1 순서로 선택했다.

선택된 C는 **S0-A + EMA α=0.5 + 연속3프레임 확인 + 확률 차이 margin0.05**다.
EMA는 `현재값 = 0.5 × 이전 EMA + 0.5 × 현재 확률`이다. 다른 상태가 현재 출력 상태보다
확률0.05 이상 높게3프레임 연속 유지되면 확정 프레임부터 상태를 변경하며 과거 출력은 수정하지 않는다.

44개 중6개(A4개/B2개)가 통과했다. B에 같은 decoder를 붙이면 validation SegmentF1은
더 높지만 fall recall이3.645%p 낮아져 안전 조건을 실패한다. 따라서 최종 C의 입력은 B가 아닌 A다.
선택은 validation만 사용했고, 선택된 조합만 test/OOD에서 평가했다.

## 결과 해석

1. **B의 학습은 유효하지만 단독 상태 모델은 미채택이다.** Validation Macro-F1은
   66.417→71.649%, fall recall65.488→79.729%로 높아졌다. 그러나 전환 감소가4.030%라
   사전 기준25%에 미달한다. Train loss는 계속 감소했지만 validation Macro-F1은epoch7 이후
   지속 개선되지 않아, 마지막epoch12가 아닌 사전 선택 규칙의epoch7을 유지했다.
2. **C의 상태 안정화 효과는 크다.** Test에서 A 대비 SegmentF1@50 +35.796%p,
   Edit +48.073%p, 전환81.589% 감소다. OOD에서도 전환81.025% 감소다.
   이 수치는 모든 class의 상태 전환이며 낙상 오경보율 감소로 해석할 수 없다.
3. **낙상 경보 관점의 손실이 있다.** C는 validation에서 fall recall 하락1.668%p로 통과했지만
   test에서는3.220%p 하락해 validation에서 허용한2%p 폭보다 크다. 낙상 F1도74.712→70.301%다.
   Validation 채택은 test 안전성 보증이 아니다. 결과 확인 후 threshold·선택을 바꾸지 않았으며
   낙상 경보 개선 모델이나 운영 채택 모델로 주장하지 않는다.
4. **OOD와 지속 상태 구분은 미해결이다.** B는 OOD 낙상 재현율을 높이는 대신 정밀도가 낮아져
   낙상 F1이51.370→50.040%로 감소했다. C의OOD Macro-F1은36.380%, lying_down F1은18.743%다.
   시간적 안정화만으로 도메인 차이나 lie_down 동작과 lying_down 상태의 혼동이 해결되지는 않는다.

## 지연·회복 진단의 경계

직접 인접한 GT 전이 뒤0~50프레임에서 successor 상태가3프레임 연속 나타나는지 조사했다.
25fps의 저장된 결과에 대한 offline 진단이며 선택에는 사용하지 않았다.

| Test 직접 GT 전이 | 안정 successor 발견/표본 | 발견된 표본의 중앙 지연 |
| --- | ---: | ---: |
| fall→lying_down | 0/8 | 없음 |
| sitting_down→sit | 285/368 | 7프레임(0.28초) |
| lying_down→getting_up | 12/16 | 6.5프레임(0.26초) |

이는 **회복 이벤트 recall이나 실제 경보 지연이 아니다.** 이전 상태의 정확성·고유 사건 대응을
요구하지 않는 successor 관찰이며, 별도 ±12프레임 직접 전이 matching에서는 test
lying_down→getting_up이0/16이다. 두 지표는 정의가 다르다.
직접fall→lying_down 표본도8개뿐이므로 전체 낙상 또는 회복 실패율로 일반화하지 않는다.
후처리 자체는 미래 입력에 따라 과거 출력을 바꾸지 않지만, 상류64프레임 encoder는 미래 문맥을
사용하므로 전체 시스템의 실시간 인과성은 보장되지 않는다.
