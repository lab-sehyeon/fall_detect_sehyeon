# GMDCSA24 성능 저하: 확인된 오류와 원인 후보

- 문서 ID: `DOC-20261002-omnifall-error-diagnosis-R1`
- 기준일: 2026-10-02
- 상태: `completed` — 저장 결과 진단; 원인별 개입 실험은 미실행

## 결론

**직접 확인된 문제는 낙상 17개 중 12개를 놓치고, 의도적으로 눕는 세 구간을 모두 낙상으로
오인한 것이다. 그 배경으로 가장 먼저 확인해야 할 조건은 학습과 시험의 시간 처리·문맥 차이다.**
차이가 존재함은 확인했지만, 그것이 성능 저하를 몇 %p 설명하는지는 아직 분리하지 못했다.

[기존 평가](2026-10-02_omnifall_gmdcsa_benchmark_shared.md)의 F1 37.04%와 예측을 그대로 두고
분석했다. 새로운 학습이나 시험 결과에 맞춘 모델·임계값 선택은 수행하지 않았다.

## 1. 서로 다른 길이의 동작을 모두 64샘플로 바꿨다

| 항목 | 학습 입력 | 이번 시험 입력 |
| --- | --- | --- |
| 시간 단위 | 연속 64프레임 window | 길이가 다른 정답 행동 구간을 균등 64샘플로 변환 |
| 라벨 | 중앙 프레임의 행동 | 구간의 행동 |
| 주변 문맥 | 중앙 프레임 앞뒤의 다른 행동을 포함할 수 있음 | 정답 구간만 사용 |
| 3D 복원·정규화 범위 | 전체 시퀀스에서 처리 후 window 추출 | 각 구간에서 새로 처리 |

프로젝트의 25 Hz 조건에서 64프레임은 약 2.56초분이며, 첫 프레임부터 마지막까지의 시간차는
2.52초이다. 반면 이번 낙상 구간의 실제 길이는 **중앙값 1.32초**이고, 17개 중 15개가
2.52초보다 짧았다. 의도적으로 눕는 세 구간은 **3.55·3.90·5.61초**였다.

이들을 모두 64샘플로 바꾸면 학습 시의 시간척도에 비해 짧은 낙상 동작은 늘어나고 긴 눕기
동작은 압축된다. 실제 구간 길이를 별도 입력으로 주지도 않는다. 이는 빠르게 넘어지는 동작과
천천히 눕는 동작의 시간적 차이를 바꿀 수 있는 조건이다.

**공식 로더가 지원하는 샘플링이라는 사실과, 우리 모델의 학습 입력에 적합하다는 검증은 다르다.**
이번 균등 64샘플은 평가 전에 고정한 모델 적용 방식이지만, 학습과 같은 시간 처리라고 설명하면
안 된다. 다만 짧은 구간에서도 정답 사례가 있고 긴 낙상에서도 오답이 있으므로 길이만으로
모든 오류를 설명하지 않는다.

## 2. 3D 모델에 제공한 문맥도 다르다

이번에는 64개의 자세를 MotionAGFormer의 입력 길이 243에 맞추면서 **마지막 자세를 179개
추가 반복**했다. 이후 실제 64개 위치의 출력만 사용한다. 학습 시 긴 시퀀스에서 3D를 복원한 뒤
64프레임을 꺼내는 방식과 입력 문맥이 다르다. 몸통 크기와 방향을 정규화하는 범위도 전체
시퀀스에서 개별 구간으로 달라졌다.

이것은 확인된 처리 차이이며, 3D 오차가 얼마나 늘었는지를 측정한 결과는 아니다. 이번 자료의
정답 3D 자세와 비교하거나 문맥 범위만 바꾼 대조를 하지 않았으므로 원인으로 확정하지 않는다.

## 3. 실제 오류는 낮은 낙상 점수와 동작 혼동으로 나타난다

| 낙상 정답 17개에 대한 현재 출력 | 개수 |
| --- | ---: |
| fall | 5 |
| other | 7 |
| lying_down — 눕는 동작 | 4 |
| lie_down — 누운 상태 | 1 |

낙상을 놓친 12개는 모두 자세 품질 검사를 통과했다. 전처리 거부 때문에 생긴 FN은 없다.
그러나 품질 검사는 검출 coverage와 confidence를 보는 기준이므로 자세의 정확성까지 보장하지 않는다.

놓친 낙상들의 fall softmax 점수는 최대 **0.1965**인데, 오경보 다섯 구간의 점수는 최소
**0.6160**이다. 모든 오경보가 모든 놓친 낙상보다 높은 점수를 받았다. 따라서 단순한 임계값
미세 조정만으로 두 집단이 잘 분리될 것이라고 볼 근거는 없다. 임계값 탐색은 수행하지 않았다.

## 4. FU의 높은 점수와 같은 평가 경로가 아니다

FU의 F1 93.333%는 Kinect 3D skeleton과 FU 이진 분류기를 사용하는 clip 평가다.
이번에는 RGB에서 사람 검출·2D 자세·3D 자세를 새로 추정하고, final J1 adapter 뒤의 별도
G0 4클래스 분류기로 구간을 판단했다. 입력 오차와 head, 표본 단위 및 가중치 평가 계보가
다르므로 동일 모델의 같은 조건에서 93%가 37%로 떨어졌다고 해석할 수 없다.

G0 자체도 기존 SAFER 평가에서 test fall F1 79.560%, OOD fall F1 53.018%로 차이가 있었다.
외부 조건에 대한 취약성은 이미 관측됐지만, 이 window 지표와 이번 segment 지표의 차이를
직접적인 성능 감소량으로 계산하지 않는다.
[기존 G0 평가](2026-09-28_global_motion_training_shared.md),
[FU 검산](2026-10-02_paper_evidence_review_shared.md).

RGB 자세 추정의 오차, 관절 좌표와 confidence 순서의 기존 제약, 학습 도메인 차이도
점검 대상이다. G0는 몸 중심의 상대 스켈레톤 표현을 사용하며 별도의 전역 이동 특징은
사용하지 않는다. 다만 어느 요소가 이번 실패를 지배했는지는 분리해 측정하지 않았다.

## 5. 라벨 의미에 대한 정정

**SAFER의 클래스 이름은 일반적인 영문 해석 및 OmniFall 명칭과 혼동하기 쉽다.**
SAFER 공식 정의에서 `lie_down`은 누운 상태이고, `lying_down`은 눕는 동작이다.
이전 설명에서 두 이름의 동작·상태 의미를 반대로 풀이한 부분은 정정해야 한다.
[SAFER 공식 논문 Appendix E](https://arxiv.org/html/2609.08038v1).

이번 오류표는 그 공식 의미에 맞춰 해석했다. 코드의 클래스 번호나 학습 라벨을 바꾼 것은 아니다.
Fall-only에서는 두 클래스 모두 음성이므로 **이번 F1 37.04%는 그대로다.**
상태·회복 감독의 의미가 올바르게 구성됐는지까지 이번 분석이 검증한 것은 아니다.

## 6. 현재 판단과 다음 검증의 범위

현재 수치는 이번 입력 연결 방식을 포함한 전체 시스템의 성능이다. 계산이 일치한다는 검산만으로
학습과 시험의 입력 의미까지 일치했다고 판단할 수 없다. 먼저 시간척도와 3D 문맥 범위를 학습
조건과 맞췄을 때 어떻게 달라지는지 별도 진단에서 확인해야 원인 기여도를 분리할 수 있다.

그 진단을 실시하더라도 기존 시험 결과를 본 뒤의 후속 분석으로 구분하고, 처음의 고정 평가를
덮어쓰지 않아야 한다. 현재 확인된 것은 실패 양상과 입력 처리 차이이며, 특정 설정을 바꾸면
성능이 회복된다는 결론은 아직 없다.
